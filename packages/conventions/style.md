# スタイルガイド

本書は、技術文書の語彙、文体、形式、表記の規則を定める。読者が解釈に迷わない文書にすることを目的とする。本書の規則は判断の基準として書き、例は1つに限る。判断に迷う場合は、本書と、各リポジトリが手本に指定した文書を参照する。

## 適用範囲

- 対象は、設計書、仕様書、README、ハンドブック、issue、PRの本文とする。
- コードのコメントは、語彙と文体を本書に従い、表記をprose-lintの規則に従う（英単語と日本語の間に空白を入れ、末尾に句点を付けない）。
- 製品の画面の文言、チャットでのやり取り、記事、英語の文書は対象外とする。

## 基調

- ソフトウェアの技術文書の語彙と、ビジネス文書の文体で書く。公式ドキュメントの日本語版や、企業の設計書に近い語感を基準にする。
- 事実、判断、条件を淡々と書く。口語、比喩、誇張、感情を表す語を使わない。
- 1つの語は1つの意味だけを持ち、1つの概念は1つの語だけで表す。
- 主語、対象、条件を省略しない。読者が文脈から補う必要のある書き方をしない。
- 情報を持たない語（「基本的に」など）を書かない。
- 平易さより正確さを優先する。ただし、漢語を重ねた硬い表現（「〜の実施を行う」など）にはしない。

## 語彙

- ソフトウェアの文脈では、ソフトウェアの分野で定着した語を使い、一般の日本語の訳語に置き換えない。独自の造語を作らない。
- システムの操作や処理は、漢語のサ変動詞で表す（「取る」ではなく「取得する」）。そのほかの和語と漢語の選択は慣用に従う。
- ドメインの概念と説明は日本語で書く。
- どちらも使われている語と、揺れやすい語は、次の表の語に統一する。表には、繰り返し揺れる語だけを追加する。

| 使う語 | 使わない語 | 補足 |
| --- | --- | --- |
| リクエスト、レスポンス | 要求、応答 | 通信の文脈 |
| 破壊的変更 | 互換性のない変更 | |
| 秘密値 | シークレット | |
| 層 | レイヤー | アーキテクチャの構成の単位。「低レイヤー」「高レイヤー」も使わない。ネットワークのL7のような定着した固有の用語は慣用のまま |
| バージョン | 版 | ソフトウェアの版を指す場合 |
| など | 等 | |

次の語は、文脈で使い分ける。

| 語 | 使う場面 |
| --- | --- |
| 形式 | データや文書の構成の種類（JSON形式、日付の形式） |
| フォーマット | 整形する行為とツール（コードのフォーマット、フォーマッター） |

製品とプロジェクトに固有の語は、各リポジトリの用語集を正本とする。

次の種類の語と表現は使わない。

| 種類 | 例 | 書き換え |
| --- | --- | --- |
| 口語 | ざっくり | 概要 |
| 比喩 | 壊れる | 失敗する |
| 曖昧な限定 | なるべく | 条件を明記する |
| 主体のない「〜します」 | 通知します | システムが通知する |
| 平易すぎる言い回し | 範囲の外 | 対象外 |

## 文体

- 常体（だ・である調）で書く。issueとPRも同じとする。
- 文末は「〜する」「〜である」を基本とする。箇条書きと表のセルは、体言止めでもよい。
- 一文には1つの内容だけを書き、短い文にする。
- 記号（`→`、`・`）で語をつなぐ略記にしない。
- 読者に語りかける表現（「〜しましょう」など）を使わない。
- 行為の主体が執筆者か読者であることが明らかな規則や手順の文に限り、主語を省略してよい。
- 決定の記録には「ユーザーの決定」と書かず、「決定（YYYY-MM-DD）」と書く。主体が意味を持つ場合は役割で書き、個人名は書かない。

要件と規則の強さは、次の語で区別する。

| 強さ | 表現 |
| --- | --- |
| 必須 | 〜しなければならない、〜する |
| 推奨 | 〜することが望ましい |
| 任意 | 〜してもよい |
| 禁止 | 〜してはならない |

## 形式

- ページ名と見出しは、文書の種類や内容を表す名詞にする（例: 「文書の書き方」ではなく「スタイルガイド」）。
- 規則ごとに例を並べない。例を並べると、その例だけが機械的に直されるためである。語の統一の表は例外とする。
- 並列の情報は箇条書き、比較と対応は表で示す。飾りとして表や、太字の見出しを付けた箇条書きを使わない。
- 表の列は1つの軸で揃える。1つの列に、種類の異なる値を混在させない。
- 選択肢の比較は、表（選択肢、利点、欠点、影響）とし、表の後に推奨と理由を書く。
- 太字は、本文中で定義する語と、警告にだけ使う。

## 表記

- 数字は半角の算用数字を使う。日付はYYYY-MM-DDとする。
- 英単語と日本語の間に空白を入れない。表示上の間隔は、CSSの`text-autospace`で付ける。
- コード上の値と環境変数はバッククォートで囲む。コミットメッセージのsubjectとPRのタイトルでは囲まない。
- 段落の文は句点で終える。箇条書きの項目は、文であれば句点で終える。見出し、表のセル、コミットメッセージのsubject、PRのタイトルには句点を付けない。
- 日本語の文の括弧は全角、コロンは半角とする。

## 検査と見直し

- prose-lintは、判断の余地がない表記（句点、空白、括弧、コロン、表記の揺れ）だけを検査する。ドメインの用語が表記の規則に当たる場合は、`prose-lint.json`の`allow`に追加する。
- 語彙、文体、形式は機械で検査しない。見直しには、日本語の文書にyomiyasu、英語のREADMEにhumanizerのスキルを使う（`.claude/settings.json`のプラグインで有効）。出力は見直しの候補であり、点数を合格の基準にしない。
