# @ryusenkei/prose-lint

A style checker for Japanese technical writing in a repository: code comments, Markdown files, and commit messages.

Rules fall into three groups:

- **Format** (`format/*`): punctuation, parentheses, colons, and spacing between Japanese and alphanumeric words
- **Style** (`style/*`): word choice (technical terms over native Japanese words, e.g. `作る` → `作成`), plain form, concise phrasing, and definite statements
- **Commit** (`commit/*`): Conventional Commits, a Japanese subject, no body, and no AI signature

## Install

```sh
pnpm add -D @ryusenkei/prose-lint
```

Requires Node.js 24 or later.

## Usage

```sh
prose-lint                      # check comments and all tracked Markdown files
prose-lint src README.md        # check specific paths
prose-lint --summary            # print counts per rule only
prose-lint --fix                # fix spacing and trailing-comment alignment in code comments
prose-lint --config lint.json   # use a specific configuration file
prose-lint --golden             # print the golden examples
```

Exits with code 1 when any issue is found, and with code 2 when the configuration is invalid. Each issue shows its rule ID, e.g. `末尾に句点を付けない [format/period]`, and the output ends with a before → after example for each rule that was hit.

Add a script to `package.json`:

```json
{
  "scripts": {
    "lint:prose": "prose-lint"
  }
}
```

## What is checked

| Source | Checked text |
| --- | --- |
| Code | Comments that start a line: `//`, `/* */` (including JSDoc), `{/* */}`, and `<!-- -->`. `#` for `tf`, `py`, `sh`, `rb`, `yaml`, `yml`, and `toml`. JSDoc `@example` blocks and fenced code are skipped |
| Trailing comments | Only in files matched by `trailingFiles` (a comment after code can't be told apart from `//` in a string) |
| Markdown | Paragraphs, list items, headings, block quotes, and table cells. Code blocks, HTML comments, front matter, and link URLs are skipped |
| Commit messages | The subject after `type(scope): `, and every other line |

Text in backticks is never checked.

Generated files are skipped, and `--fix` leaves them unchanged. A file counts as generated when its first 10 lines contain a common marker such as `Generated by`, `automatically generated`, `Code generated`, `@generated`, or `DO NOT EDIT` (for example, Wrangler's `worker-configuration.d.ts`, Payload's `payload-types.ts`, and Go code from `protoc`). You don't need to list them in `skip`.

## Rules

| ID | Rule |
| --- | --- |
| `format/period` | No `。` at the end of a line |
| `format/sentences` | One sentence per line in comments and commit subjects, up to two in Markdown (paragraphs are not wrapped) |
| `format/paren-width` | Full-width parentheses in Japanese text (use backticks for code) |
| `format/paren-nest` | No nested parentheses |
| `format/paren-count` | At most one parenthetical per line |
| `format/colon` | Half-width colon (`キー: 値`) |
| `format/spacing` | A space around words that contain letters, none around numbers (`D1 の上限`, `16人`) |
| `format/length` | Comment lines up to 100 characters (Markdown is not wrapped, so it is not checked). A URL counts as one character, since it can't be wrapped |
| `format/wrap` | No line break in the middle of a sentence in a comment (a line ending in `、` or a particle, or the next line starting with one) |
| `format/trailing-align` | Trailing comments in a block start at the same column |
| `style/vocabulary` | Preferred words and spellings (built-in list plus `vocabulary`) |
| `style/verbose` | Concise forms (`することができる` → `できる`, `確認を行う` → `確認する`) |
| `style/chain` | At most two `の` in a row (`記事の取得の結果の型` → `記事の取得結果の型`) |
| `style/hedge` | Definite statements instead of guesses (`と思う`, `かもしれない`) |
| `style/polite` | Plain form instead of `です`・`ます` |
| `commit/format` | `type(scope): subject` with a standard type and a lowercase scope |
| `commit/subject-ja` | A Japanese subject (except `chore(release): <package>@<version>`) |
| `commit/body` | Subject line only. Context goes in the PR |
| `commit/trailer` | No AI signature or trailer (e.g. `Co-Authored-By: Claude`) |

Merge, revert, and `fixup!` messages generated by git are skipped.

## Golden examples

The package ships golden examples in `golden/`: a guide to comment forms (`GUIDE.md`), sample code (`comments.ts`), and commit messages (`commit.txt`). Tests make sure they pass every rule. Print them with `prose-lint --golden`.

## AI agents

When an AI agent writes comments, run the checker after each edit so that issues, examples, and a pointer to the golden examples go straight back to the agent. For Claude Code, add a `PostToolUse` hook to `.claude/settings.json`:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write|MultiEdit",
        "hooks": [{ "type": "command", "command": "npx --no -- prose-lint --hook" }]
      }
    ]
  }
}
```

`--hook` reads the hook input from stdin and checks only the edited file, including untracked files. It exits with code 2 and writes to stderr when issues are found, which Claude Code returns to the agent. Files outside the configured paths and extensions are skipped.

## Commit messages

To check commit messages on every commit:

1. Add `.githooks/commit-msg` and make it executable:

   ```sh
   #!/bin/sh
   exec npx --no -- prose-lint --commit-msg "$1"
   ```

2. Enable the hooks directory on install, in `package.json`:

   ```json
   {
     "scripts": {
       "prepare": "git config core.hooksPath .githooks"
     }
   }
   ```

3. Keep LF line endings for hooks on Windows, in `.gitattributes`:

   ```text
   .githooks/* text eol=lf
   ```

Lines starting with `#` are ignored.

## Configuration

No configuration is needed. To change the defaults, use exactly one of these, relative to the repository root:

- `prose-lint.json`
- `.config/prose-lint.json`
- The `prose-lint` field in `package.json`

`--config <file>` takes precedence over all of them. More than one configuration, an unknown key, or an unknown rule ID is an error.

```json
{
  "paths": ["apps", "packages"],
  "extensions": ["ts", "astro"],
  "vocabulary": [{ "re": "同期ブロック", "to": "`synced_block`" }],
  "allow": ["読み物"],
  "rules": { "style/hedge": false }
}
```

| Key | Description | Default |
| --- | --- | --- |
| `paths` | Paths whose code comments are checked (git pathspec, tracked files only) | `.` (whole repository) |
| `docs` | Markdown files to check (git pathspec) | `*.md` |
| `extensions` | File extensions whose comments are checked | `ts`, `tsx`, `mts`, `cts`, `js`, `jsx`, `mjs`, `cjs`, `astro`, `vue`, `svelte`, `css` |
| `skip` | Paths to skip (regular expression) | none |
| `trailingFiles` | Files whose fields use aligned trailing comments (regular expression) | none |
| `vocabulary` | Extra word rules `{ re, flags?, to }`, added to `style/vocabulary` | none |
| `allow` | Words excluded from style rules, such as domain terms (regular expressions). Format rules still apply | none |
| `rules` | Rule IDs to turn off (`false`) | all on |
